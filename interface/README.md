# 前后端对接文档

> 这个目录是**契约**，不是说明。
> 后端（码）改了任何前端会看到的东西，必须在 `CHANGELOG.md` 里声明；
> 前端（壳）每次开工，先读这三份文件，再动手。

## 谁读、谁写

| 角色 | 读 | 写 |
|---|---|---|
| 后端（码） | 全部 | `API.md`（新增/修改接口）、`CHANGELOG.md`（每次变更） |
| 前端（壳） | 全部，**开工第一件事** | 只能写 `CHANGELOG.md` 的「前端反馈」区 |
| 论文（文） | `CHANGELOG.md`（写系统实现章节时对得上） | 不改 |

## 三条硬规则

1. **后端不静默改字段。** 改名字、改类型、改语义、删字段——都算 breaking，必须写进 `CHANGELOG.md`。
2. **前端不猜接口。** `API.md` 里标 `状态：已实现` 的才能用；标 `计划中` 的只能说"预留"，不能当已实现来渲染数据。
3. **不在对方目录里改东西。** 后端不动 `web/`，前端不动 `src/dbw/`。

## 编码规范（与实验记录一致）

| 项 | 约定 |
|---|---|
| 文件编码 | UTF-8，**无 BOM** |
| 换行 | **LF** |
| 中文标点 | 全角：，。：「」—— |
| 文件命名 | 小写 kebab-case；文档可用中文，但路径里避免空格 |
| 数字 | 结论里的数字必须能从代码或实验记录复现 |

写入方式（前端会话注意）：用 `ops_write_file` / `ops_edit_file`，不要用 Python 文本模式写文件——
那会把 `\n` 翻成 CRLF，制造"整文件改动"的假 diff（见 `experiments/11-25-1-*`）。

## 目录

| 文件 | 内容 |
|---|---|
| `API.md` | 后端对外暴露的东西：数据结构、CLI 产物、审计事件、计划中的 HTTP 接口 |
| `CHANGELOG.md` | 变更公告，日期 + 类型 + 影响 + 迁移提示 |
| `FRONTEND-BRIEF.md` | 给前端会话的操作指令（工具、编码、禁忌） |

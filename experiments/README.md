# 实验记录

> 一条硬规则：**成功和失败都要记。**
> 一次没跑通的尝试，信息量往往比一次跑通更大——它标出了边界在哪。

## 这里放什么

| 放这里 | 不放这里 |
|---|---|
| 实验目的、设置、结果、结论、局限 | 原始日志与逐条轨迹（在 `runs/`，**不入库**） |
| 复现命令 | 大段源码（给出文件路径与行号即可） |
| 失败原因，以及**当时是怎么误判的** | 只写"通过/未通过"而不写数字 |
| 关键数字的抄录 | 只引用 `runs/` 里的路径而不抄数字 |

最后一条尤其重要：`runs/` 被 gitignore，随时可能被清掉。
**结论里的每个数字，必须在本目录的文档里有一份副本。**

## 命名

```
E<三位序号>-<kebab-case 主题>.md
```

例：`E001-exact-assertion.md`、`E004-real-repo-tabulate366.md`。
序号只增不改；作废的实验保留原编号，在文末标注「已作废」并说明原因。

## 每份记录的必填字段

1. **日期**（含时区）
2. **目的**：想验证什么，预期是什么
3. **设置**：模型、任务、预算、代码路径（哪个脚本）
4. **结果**：数字，不是形容词
5. **结论**：成立 / 不成立 / 无法判断
6. **局限**：样本量、天花板、提示词路径差异等
7. **复现**：一条能跑的命令

## 累计的方法论坑

1. **n=1 会骗人**：E001 首轮得出"四组结果完全相关"，n=3 后不成立。
2. **单任务会饱和**：两个模型两条件都满分，条件差异被天花板吞掉。
3. **提示词路径不同就不可比**：E002 与 E003 的用户提示构造不同，token 不能直接对比。
4. **Windows 换行会伪造 diff**：写文件若经 Python 文本模式，`\n` 变 CRLF，整文件都算改动（E004 出现过 6001 行假 diff）。
5. **推理模型会吃光输出预算**：正文为空、`finish_reason=length`，不报错但也没答案。

# 11/24/2 · 2 人协议修复循环（真实模型）

**日期**：2026-11-24（Asia/Shanghai）
**脚本**：`scripts/run_protocol.py`
**任务**：`fixtures/repo_a`（`exact` 已摘掉，故意制造确定性失败）

## 目的

验证协议机在真实模型下可用：
第 1 轮闸门红 → 把失败明细反馈给提案座位 → 第 2 轮能否转绿。

## 设置

| 项 | 值 |
|---|---|
| 协议 | `2p.single`（提案 + 复核，无裁决） |
| 提案座位 | `deepseek/deepseek-chat` |
| 复核座位 | `ark/kimi-k3-1-pro-261024` |
| 轮次上限 | 2 |
| 契约 | `exact` 摘掉（否则一轮就过，测不到修复） |

## 结果

```
第 1 轮  提案 1 份 · 复核 0 条（丢弃 2）· 阻断 0 · 闸门 未通过（tests）
第 2 轮  提案 1 份 · 复核 1 条（丢弃 0）· 阻断 1 · 闸门 全绿

结果    accepted（第 2 轮闸门全绿）
轮次    2     token 10286     调用 4 次
```

## 结论

- **修复循环成立**：多轮 + 失败明细反馈，确实把失败救回。
- **防编造规则在真模型上生效**：复核第 1 轮提了 2 条结论，全部因缺少证据被丢弃（R-2）。
- **闸门终裁生效**：第 2 轮闸门全绿，但仍有 1 条阻断结论——系统按"闸门说了算"判交付成立。

> 这条是"判定权不外包"的现场证据：模型的意见与闸门冲突时，以闸门为准。

## 局限

1. 单任务、每格 1 次，不能排除运气；
2. 提示词路径与 `delivery.py` 不同（协议机多给了一段 doD JSON），
   因此本实验的 token 不能与 11/24/1、11/25/1 直接比较；
3. 未测"去掉复核座位"的消融，无法量化复核的边际贡献。

## 复现

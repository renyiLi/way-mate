# 11/25/17 · 把大文件收窄成"结构索引 + 报错位置原文"

**日期**：2026-11-25（Asia/Shanghai）
**任务**：`tasks/moreitertools-1248`（难档）、`tasks/tabulate-366`（易档，回归用）

## 目的

前面 11/25/12 与 11/25/16 都指向同一件事：5000 行的 `more.py` 整份塞进上下文，
模型既抄不准片段，也定位不到该改哪里（"上下文稀释"）。

这次不动提示词，改**任务预处理**：只把需要的部分喂进去。

## 实现

`delivery.focus_file(text, path, failure)`：

1. 文件 ≤ 600 行 → 原样给；
2. 否则：先给**结构索引**（所有 `def`/`class` 的行号与签名，最多 120 条）；
3. 从失败堆栈里找 `目标文件:行号`，取 ±320 行的窗口，**正文不带行号**（否则模型会把行号抄进片段）；
4. 若堆栈里找不到目标文件的行号 → **退回全文**，宁长不错。

## 踩到的坑（第一次实测没效果才发现）

第一版只按正斜杠匹配：

```python
re.findall(rf"{re.escape(path)}:(\d+)", failure)
```

而 Windows 上 pytest 报的是 `more_itertools\more.py:2347`（反斜杠），
于是永远匹配不上 → 永远退回全文 → token 几乎没变（55288 vs 55535）。

修法：把分隔符写成 `[\\/]`，并补一条"只写文件名"的兜底匹配。

## 结果

| 任务 | 收窄前 token | 收窄后 token | 变化 | 质量 |
|---|---|---|---|---|
| moreitertools-1248 | 55535 | **9069** | **−84%** | 2 条测试全红 → **过 1 红 1** |
| tabulate-366 | 33494 | 34046 | 几乎不变 | 仍全绿（回归通过） |

`tabulate-366` 没降是**正确行为**：它的失败是测试文件里的断言，
堆栈不指向目标文件 `tabulate/__init__.py`，所以按规则退回全文。

## 结论

1. **收窄有效且安全**：只在能定位故障行时生效，定位不到就退回全文。
2. **成本降 84%，质量还提升了**（从 0/2 到 1/2）——"上下文稀释"这个假说得到支持。
3. **但它救不了整个任务**：`moreitertools-1248` 对 `deepseek-chat` 仍是失败（1 红）。
   收窄解决的是"看不到/看不过来"，解决不了"改不全"。

## 触发条件（要写进第 6 章）

| 条件 | 行为 |
|---|---|
| 目标文件 ≤ 600 行 | 全文 |
| 堆栈含 `目标文件:行号` | 结构索引 + ±320 行窗口 |
| 堆栈不含目标文件行号 | 全文（安全回退） |

## 局限

1. 窗口固定 ±320 行，若修复需要跨更远的代码（如两个类互动）会漏；
2. 结构索引最多 120 条，超大文件后面的定义会被截掉；
3. 只在两个任务上验证过。

## 复现

```powershell
python scripts/run_once.py --task tasks/moreitertools-1248 --no-prepare `
  --provider deepseek --model deepseek-chat --timeout 240
```

# 11/25/16 · 让系统替提案方取原文，以及它没解决的那个问题

**日期**：2026-11-25（Asia/Shanghai）
**任务**：`tasks/moreitertools-1248`
**目标**：2 人协议的提案方在 5000 行文件上写不准 SEARCH 片段。
思路是**不让它凭记忆写，而是由系统从文件里取出原文交给它**。

## 改了三处

| 改动 | 内容 |
|---|---|
| 片段报错带原文 | 对不上时，直接附上文件里该区域的内容与行号范围，让它照抄 |
| 首行不存在时找最接近的 | 用 `difflib` 找最相似的行，连上下文一起给出 |
| `rationale` 放宽为可选 | 模型在长补丁上普遍漏这个字段，硬卡会把通路堵死 |

`rationale` 放宽的理由：它是**元数据**，不是判定依据——本课题的原则是"只有闸门判定"，
用散文字段阻断交付和这个原则自相矛盾。缺理由时记为空串，审计里仍能看到。

改完的报错长这样：

```
more.py: SEARCH 片段第 3 行与文件不一致：片段写的是 'return False'，文件第 13 行是 'return True'。
文件里该区域原文（第 10-14 行），请直接复制：
line10
    def __contains__(self, elem):
        if self._growing:
            return True
        return False
```

## 实测：信息给到了，模型还是不照抄

| 次 | 第 1 轮 | 第 2 轮 | 结果 | 失败原因 |
|---|---|---|---|---|
| 1 | 提案 1 份，红 | 提案 0 份 | rejected | `rationale` 为空（两次） |
| 2（放宽 rationale 后） | 提案 1 份，红 | 提案 0 份 | rejected | 片段第 3 行与文件不一致（两次） |

最后一次的报错已经精确到行：

```
片段写的是 'return int(q)'，文件第 2347 行是 'return 0 <= int(q) < self._len'
```

**模型拿到了原文，第二遍仍然写自己记忆里的版本。**

## 结论

1. **改进有效但不够**：报错从"找不到片段"变成"第几行、期望什么、实际什么、原文在此"，
   这是确定性的进步（已加测试锁住），但**没能让第二轮提案合法**。
2. **瓶颈不是信息不足，是模型不照抄**。它倾向凭记忆重写代码，而不是复制上下文。
3. **2 人协议在长文件任务上仍然 0 成功**（累计约 10 次运行）。
   这条通路的可用性受限于模型行为，不是我们的管道设计。

## 这就够了吗

对论文来说，这条已经可以写清楚了：

> 当任务需要修改一个模型无法完整握住的大文件时，单轮、多轮、执行循环三种流程都会失败，
> 且失败发生在不同环节；把精确原文直接喂给模型可以消除"信息不足"这一类失败，
> 但消除不了"模型不照抄"这一类失败。

这是一个有边界的结论，也是能站住的那种。

## 对下一步的提示

如果还要把 2 人协议救回来，方向不是继续改提示词，而是**缩小文件**：

- 把任务目标文件切成"相关区域 + 上下文"，而不是整份 5000 行；
- 或者干脆只把 `numeric_range` 类（约 200 行）作为 `current_file` 喂进去。

这属于"任务预处理"层面的改动，不是协议层的改动。

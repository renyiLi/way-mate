# 11/25/9 · 复核座位的 gate 语义无法用提示驯服

**日期**：2026-11-25（Asia/Shanghai）
**任务**：`tasks/tabulate-362`
**脚本**：`scripts/run_protocol.py --task ... --rounds 2`

## 目的

11/25/8 发现"复核结论 100% 因 gate 字段填错被丢弃"，本轮做了三处修复后再测：

| 修复 | 内容 |
|---|---|
| 加 `category` 字段 | 让"问题类别"有地方写，不再挤进 gate |
| gate 给枚举示例 | 提示词写明 tests/lint/api/diff 各自的含义 |
| 未知 gate 不再整条丢弃 | 记为 `unknown` 并保留；BLOCKER 降为 MAJOR |
| 非阻断结论进反馈 | 第二轮把复核建议也带给提案方 |

## 结果

三次运行，四种 gate 取值全部是**模型自创的类别名**：

```
'交付物完整性 / 可应用补丁'   '最小改动 / 定位准确性'   'deliverable-format'
'deliverable-completeness'   'semantics'   'contract'   'correctness'
'change-applicability'       'root-cause-coverage'
```

**没有一条落在 tests / lint / api / diff 上。** 给了枚举示例、给了独立字段、给了降级处理，
模型仍然照自己的语义填。

| 次 | 第 1 轮 | 第 2 轮 | 结果 | token |
|---|---|---|---|---|
| 1 | 复核 5 条（阻断 0） | 复核 4 条（阻断 0） | 未通过 | — |
| 2 | 复核 4 条 | 复核空正文 → 终止 | 基础设施失败 | 59304 |
| 3 | 复核 4 条 | 复核 4 条（阻断 0） | 未通过 | — |

## 结论

1. **`gate` 的语义无法通过提示纠正**（在该模型上）。这是本轮最硬的结论。
2. **信息不再丢失**：结论被保留下来并进入下一轮反馈，但**不参与阻断**，
   所以对结果没有影响——门禁依然只由闸门说话。
3. **2 人协议三次实验累计：1/8 有效通过**（11/25/7 的 1/2、11/25/8 的 0/3、本轮的 0/3），
   单轮基线是 1/3。**没有证据显示协作有增益。**

## 一个设计上的自我修正

强制复核结论挂到某一个闸门上，本质是**想让复核者当小裁判**——
而这与本课题"只有闸门能判定"的核心主张相矛盾。

正确的分工应该是：

| 角色 | 能做什么 | 不能做什么 |
|---|---|---|
| 复核 | 指出可疑之处、给证据、影响下一轮提案 | 判定交付是否成立 |
| 闸门 | 唯一判定 | —— |

所以 `gate=unknown` 降级为 MAJOR、不参与阻断，**不是妥协，是回到设计原则**。
下一步应该干脆把 `gate` 改成可选字段（`category` 才是语义归属），
让复核彻底变成"建议者"。

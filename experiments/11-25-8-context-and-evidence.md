# 11/25/8 · 两处改进的效果：成本降 67%，并揪出复核毁在字段语义上

**日期**：2026-11-25（Asia/Shanghai）
**任务**：`tasks/tabulate-362`
**脚本**：`scripts/run_protocol.py --task ... --rounds 2`

## 目的

针对 11/25/7 的两个问题做改进后再测：

1. 成本 4.8 倍 → 第二轮不再重发整份文件；
2. 复核结论全被丢弃 → 强化证据要求（必须给测试名或行号）。

## 设置

与 11/25/7 完全相同，仅代码不同：提案 `deepseek-chat`、复核 `flash`、2 轮、3 次、
输出预算 8192、超时 180s。

|---|---|---|---|
| 1 | ❌ | 57174 | 5 |
| 2 | ❌ | 55300 | 5 |
| 3 | ❌ | 46691 | 4 |

**通过 0/3**（前次 1/3）。样本太小，两个比例都可能是抖动，不能下"变差"的结论。

**成本 160835 → 53055（−67%）**，这一项是确定的效果：第二轮不重发整份文件、
复核提示不带全文，省下的正是重复上下文。

## 关键发现：复核不是"没证据"，是"填错了字段"

把丢弃原因打出来之后，12 条被丢弃的结论**全部是同一个原因**：

```
F1 gate 必须属于 ('tests','lint','api','diff')，实际 'deliverable-completeness'
F2 gate 必须属于 ('tests','lint','api','diff')，实际 'root_cause_accuracy'
F3 gate 必须属于 ('tests','lint','api','diff')，实际 '测试通过'
F4 gate 必须属于 ('tests','lint','api','diff')，实际 '最小改动与定位'
```

模型把 `gate` 理解成了**"这条问题属于什么类别"**，而我们的定义是
**"这条结论对应四类闸门中的哪一个"**。语义错位，导致 100% 被丢弃。

也就是说：11/25/7 里"复核座位没起作用"的归因**不完整**——
不是模型给不出证据，是它照着自己的理解填了另一个字段的语义。

## 结论

1. **成本改进成立**：−67%，来自上下文瘦身，可复现。
2. **通过率没有改善**（1/3 → 0/3），但样本不足以判定方向。
3. **复核座位失效的根因找到了**：字段命名与语义提示不清，模型自由发挥。

## 下一步（明确）

| 改动 | 说明 |
|---|---|
| 给 finding 加 `category` 字段 | 让模型把"问题类别"写在这里（自由文本） |
| `gate` 字段给枚举示例 | 提示词里直接写「如 `tests`：测试用例失败；`diff`：超出改动预算」 |
| 未知 gate 不再整条丢弃 | 记为 `gate=unknown` 并保留结论，只降级不计分 |

第三条尤其重要：现在的规则是"gate 不在枚举内就整条丢弃"，
等于**因为一个字段填错就丢掉整条可能有价值的信息**。

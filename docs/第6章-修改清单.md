## M1 · 6.1 节：两次测量不能称"同条件"

**位置**：6.1，第 7 行。

**原文**

> 此前另做过一轮每格 3 次、共 60 次的独立测量。两次测量使用同一任务集、同一模型、同一契约，仅重复次数不同，因此可以作为"总体通过率是否可复现"的对照。

**改成**

> 此前另做过一轮每格 3 次、共 60 次的探索性基线（11/26/3）。两次测量的**重复次数与日期都不同**，只能说明总体量级接近，**不构成同条件重复测量**，因此本章不以它作为"可复现性"的证据。

**依据**：31/60 采样 3 次、53/100 采样 5 次，且相隔两天（模型侧不可控因素不同）。称"同条件"是过度主张。

## M5 · 6.2 节：补一个真实 `GateReport`，并交代两道闸门在真实任务上为空

**位置**：6.2 表格之后。

**新增**

> **判定记录的形态。** 闸门输出是一条结构化 `GateReport`，固定四项、顺序固定。以
> `tabulate-366` 的一次运行（`run_id = 20261128T004952-0a936c`）为例：
>
> ```
> signature: tests:1|lint:1|api:1|diff:1   all_green: true
> tests  PASS  全部通过；通过 1
> lint   PASS  问题总数 4（基线 4，新增 0，上限 0）
> api    PASS  契约未冻结接口
> diff   PASS  改动 1 个文件 / 1 行（上限 3 / 40）
> ```
>
> 需要说明一点：**20 份真实任务的契约都没有配置 `exact` 与 `api.frozen`**，
> 因此这两道闸门在真实任务上恒为通过（`api` 的输出就是"契约未冻结接口"）。
> `exact` 与 `api` 的实际判定能力由专门用例验证：`exact` 见 6.5.1 的对照实验，
> `api` 见 `scripts/demo_gate.py` 的场景二（冻结符号缺失即拒绝）。
> 因此本章的"四类闸门"应理解为**四类判定维度**，其中 `tests`/`lint`/`diff` 在 20 条任务上
> 实际参与判定，`exact`/`api` 由专门用例覆盖。

**依据**：20 份契约实测 `exact: 0 条`、`api.frozen: 0 条`；样例取自审计摘录。

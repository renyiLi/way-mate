# 请你评审这个本科毕业设计的题目

## 背景

本科软件工程专业，2027 年 4 月下旬答辩，现在处于开题阶段（2026 年 11 月）。
指导风格偏工程，要求"能做出来、能演示、有数据"。学院模板习惯《基于 X 的 Y 系统的设计与实现》这一句式。

## 系统实际做到了什么（已跑通，不是设想）

- **可执行验收契约**：用 YAML 写死验收标准，含五类——测试命令、静态检查新增阈值、公开接口冻结、改动预算（文件数/行数/禁止路径）、精确断言（字符串必须逐字出现）。
- **四类闸门**：tests / lint / api / diff，全部结果结构化落盘。
- **精确断言自动提取**：用 AST 从 `pytest.raises(match=...)` 里静态反推"必须逐字出现的字符串"，自动进契约，并有人工确认标记与漂移检查。
- **三个座位**：提案 / 复核 / 裁决。2 人（提案+复核）、3 人（+裁决）、3 人双轨（双提案+裁决+复核），共用同一台状态机，只换排班表。
- **铁律**：只有闸门能宣布交付成立，模型之间不投票。复核说有问题而闸门全绿，交付成立。
- **审计与回放**：每次运行写 JSONL，含 run_id、git_sha、逐闸门结果、模型原始输出、token 与延迟。
- **多供应商**：一个 OpenAI 兼容适配器覆盖 DeepSeek 官方与火山方舟；方舟上一个 Key 可取用豆包、DeepSeek、Kimi 三家模型。
- **实测数据（每格跑 3 次）**：某模型无精确断言时 0/3 通过、有精确断言时 3/3 通过；另一模型两条件都通过但 token 省 58%、耗时从 110s 降到 46s；另外两个模型两条件都 3/3（天花效应，单任务区分不出差异）。
- **成长能力**：接口已预留（经验库 + 记忆钩子），默认空实现，暂不实现。
- 45 条测试，全部离线可跑，不依赖 API Key，已接入 CI。

## 已做的竞品调研（GitHub star 数为实测）

- 巨型 coding agent：openai/codex 13.6 万、gemini-cli 10.9 万、OpenHands 9.4 万、cline 7.2 万、aider 5.0 万。

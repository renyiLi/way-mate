# 4 小时/天 排期与工程纪律（定稿版）

> 基准：今天 2026-11-22，答辩 2027-04 下旬。共 22 周，其中春节 3 周、期末考 2 周基本作废，**有效 17 周**。

## 一、先把账算清楚

4 小时/天 × 7 天 = 28 小时/周 × 17 周 ≈ **476 小时**。

扣除状态差的时段（按 75% 折算）≈ **357 有效小时 ≈ 45 个标准工作日**。

其中论文、查重、PPT、彩排必须预留 **80–90 小时**，那么**留给系统的只有 ≈ 270 小时 ≈ 34 个工作日**。

### 34 个工作日要装下的东西

| 模块 | 估算 | 备注 |
|---|---|---|
| 契约 DSL + 闸门引擎 | 35h | 最核心，最先做，不返工 |
| Provider 适配层（DS/Kimi/OpenAI 兼容） | 30h | 方言归一化是真成本 |
| 编排状态机 + 修复循环 | 35h | |
| 沙箱执行器 | 20h | Docker / WSL2 |
| 审计 + 重放 | 18h | 论文护城河，不能省 |
| 前端三视图 | 55h | **六视图砍到三视图** |
| 任务集 20 条（含隐藏测试） | 25h | 手写，不能自动化 |
| 实验脚本 + 跑数 | 20h | |
| 联调、修 bug、返工 | 30h | 永远被低估，按 15% 预留 |
| **合计** | **268h** | 刚好贴合 |

**结论：紧，但可行。前提是立刻砍掉下面第五节那五项。**

## 二、"论文很简单"——对一半，错一半

对的部分：本科论文的写作本身确实不难，格式化的章节结构写起来很快。

错的部分：**第 6 章（实验）不是写出来的，是系统跑出来的。** 而实验数据只能在系统具备埋点能力之后才存在。把论文放最后的真实后果是：

1. 系统做完了但没有结构化日志 → 补埋点 → 系统已改版 → 前期数据不可信，必须全部重跑；
2. 任务集在实验中途被修改 → 基线前后不可比 → 数据作废；
3. 论文里的数字对应不上仓库任何一个状态 → 老师问"这个 62% 是怎么来的" → 当场答不出。

**这三条一旦发生，就是两周起步的重做，而你的四月没有两周。**

### 所以：把论文的三个硬需求，提前变成三条工程约束

从第一个 commit 起就遵守，一分钱不多花，但省下最后三周：

| 约束 | 具体要求 | 对应论文 |
|---|---|---|
| **每次运行必须落一条记录** | JSONL 一行：`run_id, git_sha, provider, role, prompt_hash, tokens_in/out, latency_ms, gate结果逐项, repair_round, human_decision` | 第 6 章全部图表 |
| **任务集进仓库并打 tag** | 公开测试与隐藏测试分离，隐藏测试在被测代码之外 | 第 6.2 节 |
| **每次正式实验单独归档** | `experiments/<日期>-<git_sha>/` 存全部原始 JSONL + 汇总 CSV | 第 6 章可复现性附录 |

做到这三条，"论文很简单"这句话就成立；做不到，它就是个陷阱。

## 四、每天 4 小时怎么切

```
3h00m  写代码 / 调试系统
0h30m  当天决策记录（decision log）→ 直接变成论文第 5 章素材
0h30m  跑一次回归（demo 脚本），确认主干仍然可运行
```

**核心纪律：主干永远可运行。** 宁可功能少，不可 demo 挂。每次下班前，`scripts/demo_gate.py` 必须通过。

## 五、现在就可以砍掉的五项（换回约 60 小时）

| 砍掉 | 换成 | 省 |
|---|---|---|
| 六视图 → 三视图（任务、运行审查、签核） | 其余三个并入"运行细节"页 | 35h |
| 用户体系 / 权限 / 多租户 | 单用户本地运行 | 10h |
| 多语言 / 多仓库形态 | 只支持 Python + pytest | 10h |
| 流式输出 | 轮询 + 进度条 | 5h |
| 模型自动路由 / 自动选型 | 配置文件写死角色→模型 | 5h |

这五项写进论文的"非目标"与"展望"，不减分，反而显得有判断力。

## 六、Codex 的正确处理（不改排期）

- 适配层写成 **OpenAI Responses API 兼容**，对方给 key 即可用，代码量约 2 小时；
- 第三家缺席时，用 **DeepSeek 扮演第三个角色**（同厂商不同角色）完成闭环，实验表里明确标注；
- 所有模型响应**落盘为 fixture**，答辩用固定回放 —— 断网、欠费、模型下线都不影响演示；
- 论文里把这个能力称为**"可重放性"**，写进第 5 章关键设计。资源风险 → 架构卖点。
